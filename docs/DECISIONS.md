# Decisions

ADR-style log. Each entry: decision, date, why.

---

## ADR-001: `// SAFETY:` is the only allowed code comment

- **Date:** 2026-10-27
- **Decision:** Code has no comments, with one exception: every `unsafe` block carries a one-line `// SAFETY:` comment stating the invariants that make it sound. Enforced by `#![deny(clippy::undocumented_unsafe_blocks)]` in `ghostty-vt-sys`, `ghostty-vt` and the platform crates.
- **Why:** A `SAFETY` comment does not restate code; it records a manually checked invariant the compiler cannot verify and types cannot express (ownership across FFI, thread affinity, pointer validity). The project has heavy FFI against an alpha C API (libghostty-vt) and Win32/D3D11/DirectWrite/ConPTY, so these invariants must be reviewable and greppable when the pins are bumped.
- **Constraints:** `unsafe` blocks stay minimal and are wrapped in RAII owners (`Drop`, `NonNull`) so each invariant lives in one place. No other comments anywhere.

## ADR-002: Code written in WSL, built and run on Windows (superseded by ADR-007)

- **Date:** 2026-10-27
- **Decision:** Code is written in the WSL checkout, and only what Linux can check is verified there (platform-agnostic crates, the libghostty-vt build, smoke tests). `optimum.exe` is built natively on Windows with the MSVC toolchain and checked there by hand.
- **Why:** Optimum is a Windows binary. Building inside WSL produces a Linux binary, and only a real Windows machine and monitor can show the window, the input and the text clarity.

## ADR-003: Keep libghostty-vt, with Zig as a build-only tool

- **Date:** 2026-10-27
- **Decision:** The VT core stays libghostty-vt, built from source by `ghostty-vt-sys`'s `build.rs`. The pin is Ghostty `4a4fc017940bec38c93b278c10c6a18c591f3e63` (`main`, version 1.4.1-dev), built with `zig build -Demit-lib-vt=true`. That commit's `build.zig.zon` requires Zig `0.17.0` (`minimum_zig_version`). Zig is installed on Windows via winget (`zig.zig` 0.17.0) and in WSL at `~/.local/zig` (official tarball, sha256 checked).
- **Why:** There is no C implementation of libghostty-vt, and libvterm is weaker. Pure-Rust cores either have weak grapheme support and no key encoder (`alacritty_terminal`) or are not published as a standalone crate (`wezterm-term`). Zig is needed only at build time: no Zig code of ours, no Zig in the shipped binary.

## ADR-004: Bindings generated by bindgen at build time

- **Date:** 2026-10-27
- **Decision:** `ghostty-vt-sys` runs `bindgen` in `build.rs` on every build; no generated bindings are committed. The build host therefore needs libclang (`LIBCLANG_PATH`); CI uses the LLVM preinstalled on `windows-latest`.
- **Why:** The C API is alpha and changes with each pin bump. Build-time generation always matches the pinned headers and the target's ABI, with no regeneration step to forget.

## ADR-005: libghostty-vt optimize mode follows the Cargo profile

- **Date:** 2026-10-27
- **Decision:** Cargo `release` builds libghostty-vt with `ReleaseFast`; every other profile uses `ReleaseSafe`.
- **Why:** Zig `Debug` is too slow for a terminal under real output. `ReleaseSafe` keeps Zig's safety checks during development, `ReleaseFast` ships.

## ADR-006: libghostty-vt is linked statically

- **Date:** 2026-10-27
- **Decision:** Link `ghostty-vt-static.lib` (Windows) / `libghostty-vt.a` (elsewhere). No DLL is shipped.
- **Why:** One `optimum.exe` with no extra DLL to keep in sync. Ghostty's static archive bundles its SIMD dependencies and compiler_rt, so it is meant for this.

## ADR-007: Cross-compile from WSL to `x86_64-pc-windows-gnu` with Zig as the linker

- **Date:** 2026-10-27
- **Decision:** All development and building happen in WSL. The Windows target is `x86_64-pc-windows-gnu`, linked by `zig cc` through `cargo-zigbuild`; libghostty-vt is built with `-Dtarget=x86_64-windows-gnu`. Tests run as real Windows executables via WSL interop (`cargo-zigbuild test --target x86_64-pc-windows-gnu`). CI builds the same target on `windows-latest`. Supersedes ADR-002.
- **Why:** all work happens in WSL and the `.exe` just runs on Windows; nothing (Build Tools, Rust, LLVM) has to be installed on Windows. Tests run on Windows straight from WSL.
- **Rejected: `x86_64-pc-windows-msvc` via `cargo-xwin`.** Rust links fine, but Ghostty's build runs `translate-c` (on Wuffs) as a separate tool that never receives the MSVC SDK include paths when cross-compiling, so `stdlib.h` is not found. Fixing it needs a Ghostty patch, which we don't carry.
- **Consequences:** MinGW ABI and runtime instead of MSVC; Rust debug info is DWARF, not PDB (debug with WinDbg/VS is weaker; gdb/lldb work). Win32, D3D11 and DirectWrite through `windows-rs` are unaffected by the ABI choice. Revisit MSVC if a real blocker appears.

- **Date:** 2026-10-27

The files are committed under `vendor/conpty/x64/` unmodified; `optimum-win`'s `build.rs` copies them next to the built executables. Bump in its own commit.

## ADR-009: PTY threading and shutdown order

- **Date:** 2026-10-27
- **Decision:** Each session runs two threads. `pty-reader` does blocking `ReadFile` on the output pipe and delivers `PtyEvent::Output` through a caller-supplied callback. `pty-waiter` waits for the process, closes the pseudoconsole (which ends the output pipe), joins the reader, then delivers `PtyEvent::Exited(code)`. So all output always arrives before the exit event, and only one thread ever calls the callback at a time. Input is written synchronously with `WriteFile` from the owner's thread.
- **Why:** ConPTY keeps the output pipe open after the child exits until `ClosePseudoConsole`; closing must happen while the reader is still draining, or older ConPTY versions block. The callback (instead of a fixed channel type) lets M2 post window messages directly.
- **Known gap:** a large paste can block on `WriteFile` if the child stops reading; revisit with a writer thread in M5 (right-click paste).

## ADR-010: WSL availability check

- **Date:** 2026-10-27
- **Decision:** `WslStatus::detect()`: `%SystemRoot%\System32\wsl.exe` missing → `NotInstalled`; `wsl.exe --list --quiet` failing or listing nothing → `NoDistribution`; otherwise `Ready`. Both failure states tell the user to run `wsl --install`. `wsl --list` does not boot the WSL VM, so the check is cheap; in M2 it runs off the UI thread.
- **Why:** detection relies only on the exe's presence, exit code and output. Without the WSL feature, `wsl.exe` still exists as a stub and `--list` fails, which lands in `NoDistribution`; the remedy is the same command.

## ADR-011: Per-Monitor v2 DPI awareness set by API, not manifest

- **Date:** 2026-10-27
- **Decision:** `run()` calls `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` before any window exists. No application manifest is embedded.
- **Why:** embedding a manifest needs a resource compiler step (`windres`/`llvm-rc`) in the cross build, i.e. a non-Rust build step. The API call has the same effect when made first. Revisit if a manifest becomes necessary for something else (e.g. an icon resource, M8).

## ADR-012: Frameless window and single instance (M2)

- **Date:** 2026-10-27
- **Window:** `WS_OVERLAPPEDWINDOW` + `WS_EX_NOREDIRECTIONBITMAP`; `WM_NCCALCSIZE` returns 0 (client = whole window, inset by the frame thickness when maximized); `DwmExtendFrameIntoClientArea` with 1 px margins keeps the shadow; `DWMWCP_ROUND` corners on Windows 11; `WM_NCACTIVATE` passes `lParam = -1` so Windows never repaints a frame. `WM_NCHITTEST`: resize borders = `SM_CXFRAME + SM_CXPADDEDBORDER` for the window's DPI (none when maximized), the top padding (12 px scaled) is `HTCAPTION`, the rest `HTCLIENT`. Initial size 1000×640 at 96 DPI, scaled; minimum 240×160.
- **D3D11:** hardware device, WARP fallback; flip-discard swap chain, `B8G8R8A8_UNORM`, `DXGI_SCALING_NONE`; `MakeWindowAssociation(NO_ALT_ENTER | NO_WINDOW_CHANGES)` so DXGI adds no Alt+Enter shortcut. A failed present or resize recreates the renderer.
- **Re-entrancy:** the window procedure borrows the `App` only inside `handle()`; calls that can dispatch nested messages (`SetWindowPos`, `ShowWindow`, `SetForegroundWindow`, `DestroyWindow`, `DefWindowProcW`) run after the borrow ends.
- **Single instance:** mutex `Local\Optimum-01bf42e0-0eca-4d06-8a99-579ea7c5038f`; a second process finds the window by class `Optimum.Window.<same id>` (retrying for up to 2 s), calls `AllowSetForegroundWindow`, posts the registered message `Optimum.Activate.<same id>`, and exits 0. The first process restores and foregrounds itself.
- **Startup:** the window is shown and cleared before WSL is touched; WSL detection and the ConPTY spawn run on a worker thread and report back via a queue + `PostMessageW`. Output that arrives before the session exists is buffered.
- **Temporary, until text rendering exists:** `CellSize::placeholder` (9×18 px at 96 DPI) sizes the grid; closing the window closes it without the M5 warning overlay; a missing WSL only stores the message for the M5 overlay; background is a fixed `#121212` until config (M6). Tiling window managers (e.g. GlazeWM) override the initial size, as expected.

## ADR-013: Linux is a target platform

- **Date:** 2026-10-27
- **Decision:** Optimum targets Windows (WSL-first), macOS and Linux. Windows stays first; the order of macOS and Linux is open. Linux gets its own platform crate (`optimum-linux`), a login shell like macOS, `$XDG_CONFIG_HOME/optimum/config.toml`, `xdg-open` for `Ctrl+,`, `tcgetpgrp` for the close warning, and a `flock`-based single instance.
- **Why:** the same terminal is planned for all three desktop systems.
- **Open:** Wayland/X11, GPU API, rasterizer (FreeType + HarfBuzz vs. the native-APIs-only rule for the render path), PRIMARY selection, decorations on Wayland. To be decided before Linux work starts.

## ADR-014: Text pipeline (M3)

- **Date:** 2026-10-27
- **Rasterization:** DirectWrite only. One glyph per `IDWriteFactory2::CreateGlyphRunAnalysis`, rendering mode from `GetRecommendedRenderingMode` with the system rendering params (`OUTLINE` replaced by `NATURAL_SYMMETRIC`), natural measuring, default grid fit, baseline origin (0, 0). ClearType: `CLEARTYPE_3x1` RGB coverage; grayscale: `ALIASED_1x1` coverage with grayscale antialiasing. Coverage is linear: gamma and enhanced contrast are applied in the pixel shader, as DirectWrite expects (math and gamma-ratio table ported from Windows Terminal's AtlasEngine, MIT, noted in THIRD_PARTY_NOTICES).
- **Defaults:** antialiasing follows `SPI_GETFONTSMOOTHINGTYPE` (ClearType if the system uses it, else grayscale); gamma, ClearType contrast and grayscale contrast come from `IDWriteFactory::CreateRenderingParams()`. Overrides arrive with the config (M6) and the debug overlay (M7).
- **Font:** `Cascadia Mono` 12 pt (falls back to `Consolas` if missing), line height 1.0; bold/italic via `GetFirstMatchingFont` (DirectWrite simulates missing styles). Missing glyphs go through `IDWriteFontFallback::MapCharacters` with a small COM `IDWriteTextAnalysisSource`.
- **Cell metrics** (same rules as AtlasEngine): width = round(advance of `0`), height = round((ascent + descent + lineGap) × line height), baseline = round(ascent + (lineGap + height − natural height) / 2); underline/strikethrough from the font metrics, rounded, thickness ≥ 1 px. All integers.
- **Pixel-grid discipline:** glyph quads sit at `cell origin + baseline + glyph bounds`, all integers; the pixel shader reads the atlas with `Texture2D.Load` (exact texel fetch, no sampler, no filtering); no transforms.
- **GPU:** one instanced draw per frame (triangle-strip unit quad + 20-byte instances: position, size, atlas coords, RGBA, shading type). Dual-source blending (`ONE` / `INV_SRC1_COLOR`) handles solid quads, grayscale and ClearType in one pass. Atlas: one 2048² RGBA8 texture, shelf packing, cleared and refilled when full.
- **Dirty rows:** libghostty-vt's render state reports dirty rows; `Frame` copies only those, the renderer rebuilds instances only for those rows and reuses the rest. Nothing is presented unless PTY output, a resize, a DPI change or a paint request happened.
- **Shaders** are HLSL compiled at startup with `D3DCompile` (d3dcompiler_47, part of Windows 10+): no shader compiler in the cross build.
- **Known gaps (later milestones):** multi-codepoint graphemes (ZWJ emoji, combining marks) draw only the base code point until shaping with `IDWriteTextAnalyzer`; no color emoji; box-drawing/block glyphs not procedural yet; no ligatures; BGR subpixel panels not handled; cursor does not blink (the hollow unfocused cursor arrived in M4).
- **Provisional theme** until M6: foreground `#d4d4d4`, background `#121212`, cursor = foreground, palette = libghostty-vt's default (xterm).

## ADR-015: Input (M4)

- **Date:** 2026-10-27
- **Keyboard:** the physical key comes from the scancode (set 1 + extended bit); numpad keys are told apart by their virtual key (digit vs. navigation). The text for a key comes from the `WM_CHAR`/`WM_SYSCHAR` messages that `TranslateMessage` queued for it, taken with `PeekMessageW` (the winit approach). So dead keys and AltGr come out exactly as Windows composes them. A pending `WM_DEADCHAR` sends nothing.
- **Event rules for libghostty-vt's encoder:**
  - printable text with Ctrl+Alt held is treated as AltGr: Ctrl and Alt are dropped and the text is sent;
  - when Ctrl or Alt yields no printable text, the text is recomputed by `ToUnicodeEx` with Ctrl/Alt cleared, using the no-state-change flag (Windows 10 1607+) so dead keys survive;
  - the unshifted code point comes from `ToUnicodeEx` with an empty key state;
  - Shift counts as consumed when the key produced text;
  - control characters are never passed as text.

  The encoder then handles legacy, DECCKM, modifyOtherKeys and the kitty protocol, including Ctrl on Cyrillic layouts.
- **Only shortcut:** `Ctrl+,` = physical Comma key with exactly Ctrl (lock keys ignored). It works on any layout. Its press and release are swallowed. Until M6 it does nothing else.
- **Alt+F4** goes to `DefWindowProc` (OS close). Every other `WM_SYSKEYDOWN`/`WM_SYSKEYUP` is handled by Optimum, so Alt, F10 and Alt+Space reach the shell instead of activating the system menu.
- **IME:** IMM32. The default composition window is hidden (`ISC_SHOWUICOMPOSITIONWINDOW` cleared). The preedit string is drawn by our renderer at the cursor: background, glyphs, underline and a caret. The candidate window is anchored to the cursor cell with `CFS_EXCLUDE`. Committed text is written to the PTY unencoded. TSF can replace this later.
- **Mouse:** reported through libghostty-vt's encoder only while the app enabled mouse tracking.
  - Shift held means not reported (reserved for native selection in M5).
  - The wheel is reported per 120-unit notch, as buttons 4/5 (vertical) and 6/7 (horizontal).
  - XButton1/2 map to buttons 8/9.
  - Mouse capture is taken on any button press and released when none is held.
  - The pointer is an I-beam, or an arrow while the app tracks the mouse.
- **Focus:** focus in/out reports when mode 1004 is set. The block cursor becomes hollow when the window is unfocused.
- **Re-entrancy:** `PeekMessageW`, IMM context reads, `SetCapture`, `ReleaseCapture`, `SetCursor` and IME window placement run outside the `App` borrow, in the window procedure.
- **Deferred to M5:** selection, right-click paste, wheel scrollback, alternate-scroll (1007), scroll-to-bottom on input.

## ADR-016: App icon

- **Date:** 2026-10-27
- **Source:** the project's own artwork. The first versions came as an SVG and a 1024 px PNG. On 2026-10-28 it was replaced by the dark version (`optimum-icon-dark`), and the `.ico` was regenerated the same way. The same day the transparent margin and soft shadow around the tile were cropped away (tile 100…923 of 1024, upscaled to fill the canvas; SVG `viewBox="100 100 824 824"`), so the icon fills its whole slot in Start, the taskbar and Explorer.
- **`assets/optimum.ico`** is generated from the 1024 px PNG: frames at 16, 20, 24, 32, 40, 48, 64, 96, 128 and 256 px, each PNG-compressed, high-quality bicubic downscale (.NET `System.Drawing`, run once by hand). It is committed, so the build needs no image tools. Regenerate it whenever the artwork changes.
- **Gold icon (2026-10-28, evening):** a new gold icon, supplied as a finished `.ico` (PNG frames 16, 20, 24, 32, 40, 48, 64, 256) plus matching PNGs. `assets/optimum.ico` is now that file as-is; the PNGs are in `assets/png/`. The earlier SVG and 1024 px PNG were removed.
- **Embedding:** `crates/optimum/build.rs` turns the `.ico` into a `.res` file (RT_ICON + RT_GROUP_ICON, id 1) in pure Rust and passes it to the linker. zig/lld accepts `.res` directly, so there is no `rc.exe`/`windres` step.
- **Window:** `WM_SETICON` with big and small icons loaded at the window's DPI (`SM_CXICON` and `SM_CXSMICON`), re-applied on `WM_DPICHANGED`; replaced icons are destroyed.

## ADR-017: Daily-driver basics (M5)

- **Date:** 2026-10-27
- **Selection:** libghostty-vt's selection gesture state machine. Single click places the anchor and clears the selection, double click selects a word, triple click a line, drag extends by cell, word or line. Click timing uses `GetDoubleClickTime`; repeat distance is `SM_CXDOUBLECLK / 2`. The selection is installed into the terminal (`OPT_SELECTION`), so it is tracked across output and reflow. The render state reports it per row, and `Frame` draws selected cells inverted.
- **Copy:** on left-button release, a non-empty selection is formatted as plain text (unwrap + trim) and put on the clipboard (`CF_UNICODETEXT`, LF→CRLF).
- **Mouse mode:** selection happens when the app has not enabled mouse tracking, or when Shift is held. Otherwise clicks go to the app (ADR-015).
- **Paste:** right-click pastes when the click is not reported to the app. `ghostty_paste_encode` replaces unsafe control bytes with spaces, wraps the text in bracketed paste when mode 2004 is set, and otherwise turns newlines into CR.
- **OSC 52:** program clipboard writes (OSC 52 / OSC 1337 Copy / OSC 5522, `text/plain` only) go to the Windows clipboard. Clipboard reads are never answered (privacy, same as Windows Terminal).
- **Clipboard calls** run after the `App` borrow ends (`EmptyClipboard` can send `WM_DESTROYCLIPBOARD` to us). They retry `OpenClipboard` 10× 5 ms.
- **Scrollback:** without mouse tracking, the wheel scrolls the viewport by the system's `SPI_GETWHEELSCROLLLINES` per notch.
  - On the alternate screen, the wheel sends arrow keys if mode 1007 is set and nothing otherwise.
  - Any key that produces output, typed or IME text, and paste all jump back to the bottom.
  - The viewport is not moved by new output.
- **Synchronized output (2026):** the `RENDER_HOLD` callback captures the frame into the render state at the moment the hold begins, during `write_capturing`. The render state is not updated again until the hold ends. A 250 ms timer releases a hold older than 1 s by resetting the mode.
- **Close warning:** `WM_CLOSE` while the shell is alive shows a centred in-window panel: "A process is still running. Close anyway? / Enter to close · Esc to cancel".
  - While the panel is up, only Enter, Esc and Alt+F4 are handled. A second `WM_CLOSE` closes.
  - The shell exiting by itself still closes immediately.
- **WSL missing / spawn failure:** the stored message is drawn in the same panel, word-wrapped to the window. The window stays until the user closes it.
- **Known gaps:**
  - dragging a selection past the top or bottom edge does not autoscroll yet;
  - selection colour is plain inversion until config (M6);
  - the WSL-missing panel is not verified on a machine without WSL;
  - moving between monitors with different DPI is not re-tested yet (the M3 path re-rasterizes).

## ADR-018: Settings (M6)

- **Date:** 2026-10-27
- **File:** `%APPDATA%\Optimum\config.toml`, located with `SHGetKnownFolderPath(FOLDERID_RoamingAppData)`. Parsed in `optimum-core` (`serde` + `toml` with only `parse`, `serde` and `std` features; neither crate does any I/O beyond what we hand it). Unknown keys are errors (`deny_unknown_fields`), so typos are reported.
- **Keys** (all look and feel):
  - `[font] family, size, line_height`
  - `[text] antialiasing, gamma, contrast`
  - `[colors] foreground, background, cursor, selection, palette` (exactly 16)
  - `[cursor] style, blink`
  - `[window] padding, opacity`

  Ranges: size 4–96 pt, line_height 0.5–3, gamma 1.0–2.2, contrast 0–10, padding 0–200, opacity 0.1–1. `"system"` keeps the DirectWrite value. `contrast` sets both the ClearType and the grayscale enhanced contrast. `cursor = "foreground"` follows the text colour. Missing keys take their defaults, so an empty file is valid.
- **Not included:** `ligatures`. There is no shaping yet (ADR-014), so the key would do nothing. It will be added together with shaping.
- **Defaults file:** written on the first `Ctrl+,`. It contains every key with its default and a short comment. A test asserts that the file parses to exactly `Config::default()`.
  - The default palette is Ghostty's 16 colours, so nothing changed visually.
  - Indices 16–255 are the xterm cube and grey ramp.
  - The default selection colour is `#264f78`; selected cells keep their text colour.
- **`Ctrl+,`:** `ShellExecuteW("open")` on the file. If no program is associated (result ≤ 32), Notepad is used. The call runs outside the `App` borrow.
- **Hot reload:** a watcher thread waits on `FindFirstChangeNotificationW` for the folder (last-write and file-name changes, so editors that save by rename work) and posts `ConfigChanged`. The UI re-reads the file and applies it only if the parsed value changed:
  - the renderer rebuilds the fonts and atlas only when the font or text settings changed;
  - the session applies colours, palette, default cursor style and blink, and a fresh render state recolours every cell;
  - the grid is recomputed for the new cell size and padding.

  The watcher starts at launch if the folder exists, or after the first `Ctrl+,`.
- **Errors:** the last good config stays active. A one-line strip at the bottom of the window shows `config.toml:<line>: <message>` until the file parses again. Line numbers come from `toml` spans, plus `Spanned` values for range checks.
- **Cursor blink:** follows libghostty-vt's cursor blinking state, so `blink` sets the default and DECSCUSR can override it. The timer uses `GetCaretBlinkTime` and runs only while focused. A key press shows the cursor again.
- **Opacity:** whole-window alpha via `WS_EX_LAYERED` + `SetLayeredWindowAttributes`, removed again at 1.0. Text becomes translucent as well. Per-pixel background-only transparency would need a composition swap chain and would cost ClearType, so it was not done.
- **Verified live:**
  - editing the file updates the window within about a second;
  - an out-of-range value shows `config.toml:42: opacity must be between 0.1 and 1` while keeping the old config;
  - a colour change recolours existing text;
  - `opacity = 0.85` sets the layered alpha to 217 and the window keeps rendering.

  Not verified live: `Ctrl+,` opening an editor (that needs a key press), and how the translucency looks on screen.

### ADR-018 addendum: translucency and blur (2026-10-28)

- **First attempt failed:** layered whole-window alpha (`WS_EX_LAYERED`) combined with `DWMWA_SYSTEMBACKDROP_TYPE`. The backdrop was never visible, because the swap chain content above it was opaque.
- **Now:** the renderer presents through DirectComposition, with `CreateSwapChainForComposition`, premultiplied alpha and one visual on the window, which was already `WS_EX_NOREDIRECTIONBITMAP`. `opacity` applies to the default background only: the clear colour is premultiplied with that alpha. Text, cursor, selection and non-default cell backgrounds stay opaque. The layered style is no longer used.
- **ClearType:** it cannot be blended onto a translucent background, so text switches to grayscale antialiasing while `opacity < 1`, the same rule as Windows Terminal's AtlasEngine. At `opacity = 1` nothing changes.
- **`[window] blur = false`:** when it is on and `opacity < 1`, the window gets `SetWindowCompositionAttribute(WCA_ACCENT_POLICY, ACCENT_ENABLE_BLURBEHIND)`. This is a plain Gaussian blur of what lies behind the window, tinted only by our own background colour at `opacity`, which is close to how Windows Terminal's acrylic looks. The function is an undocumented user32 export, resolved with `GetProcAddress`; if it is missing, blur silently does nothing.
- **Rejected:** the documented `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_TRANSIENTWINDOW`, tried first.
  - It needs the frame extended over the whole client area (−1 margins). DWM then draws its own minimise, maximise and close buttons, which do nothing in our frameless window and break the "no chrome" rule.
  - Its acrylic adds a light grey luminosity layer, which looks washed out.
  - The frame stays at the 1 px margin from ADR-012.
- **Frame margins are 0** (added 2026-10-28). The cause of "opaque when focused, transparent when not": with `DwmExtendFrameIntoClientArea` at 1 px, Windows 11 paints the frame's dark caption material under the whole client area while the window is active. A transparent background shows it, so the window looked opaque.
  - Found with the debug tuner's frame variants. Transparency appeared only with margins 0, both with and without `WS_CAPTION`.
  - `WS_CAPTION` is kept, for Snap and animations, and the margins are now 0. This supersedes the 1 px margin in ADR-012.
  - `DWMSBT_NONE` stays as a harmless explicit default.
- **System backdrop forced off** (added 2026-10-28). The window sets `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_NONE` at creation.
  - Without it, the default `DWMSBT_AUTO` let Windows 11 draw its own dark backdrop behind the window while it was active.
  - Measured: at `opacity` 0.1 a uniform dark-grey layer showed through instead of the wallpaper, and only while focused. The window therefore looked opaque when active and transparent when inactive.
  - Ghostty on the same machine does not show this.
- **Cell backgrounds are translucent too** (added 2026-10-28). `opacity` now applies to every cell background, written premultiplied and replacing the destination, not just to the default background. Text, cursor and overlay panels stay opaque.
  - Why: TUIs such as herdr, tmux status bars and nvim themes paint an explicit background on every cell. Those cells used to stay opaque, so Optimum looked opaque whenever such an app filled the screen.
  - herdr paints its background only while focused (focus reports, mode 1004). That made the window look opaque when focused and transparent when not, which seemed like inverted logic.
  - Measured: the focused window showed exactly herdr's `#202021`.
  - This matches Ghostty with `background-opacity-cells = true`.
- **Verified live:** the DirectComposition translucency (text stays opaque). The accent blur was verified later by eye.

## ADR-019: Clarity tooling (M7)

- **Date:** 2026-10-28
- **Tuner:** a panel compiled only in debug builds (`#[cfg(debug_assertions)]`, module `tuner`), toggled with `Ctrl+Shift+F11` or `Ctrl+Shift+F12` (F11 was added because F12 is often grabbed by Steam and game overlays; the numpad arrows work too). Release builds contain neither the key nor the code; this was checked by searching the release exe for the panel's strings.
  - While the panel is open, the arrow keys and Esc belong to it, and every other key still goes to the shell.
  - It edits the live `TextParams`: antialiasing, gamma, ClearType and grayscale enhanced contrast, ClearType level. It also edits the font size and line height, which rebuilds the fonts and resizes the grid.
  - Nothing is persisted; good values go into `config.toml` by hand.
  - The panel reuses the overlay renderer. Its lines are padded to equal width, so the centred panel reads as left-aligned columns.
- **ClearType level:** now honoured. The system value comes from `IDWriteRenderingParams::GetClearTypeLevel`, and the shader blends the subpixel coverage towards its grey average: `lerp(avg(rgb), rgb, level)`. At the usual 1.0 nothing changes. It is not a `config.toml` key yet; it becomes one only if tuning shows it matters.
- **Shader regression test:** `shaders_compile` runs `D3DCompile` on both entry points in the Windows test run, so HLSL errors surface without opening a window.
- **Comparison:** `docs/clarity/sample.txt` (stems, ambiguous glyphs, Cyrillic, colours, weights, box drawing, CJK) and `docs/clarity/compare.ps1`.
  - The script captures Optimum and Windows Terminal with `PrintWindow(PW_CLIENTONLY | PW_RENDERFULLCONTENT)`, so it works on covered windows and needs no focus changes.
  - It writes native crops, a nearest-neighbour zoom side by side, and a diff image with the mean difference.
  - Procedure: `docs/clarity/README.md`.
- **Status:** the tooling is built and unit-tested (tuner stepping and ranges, toggle key, panel layout, shader compile; the script is parse-checked). Tuning and sign-off are done by eye on a real monitor; see ADR-023.

## ADR-020: Bundled default font: JetBrains Mono Nerd Font

- **Date:** 2026-10-28
- **Decision:** the default font is **JetBrainsMono Nerd Font**, embedded in `optimum.exe`, so every install gets the same font plus Nerd Font icons (starship, lsd, nvim) without installing anything. There is one font only, no separate icon fallback.
- **Source:** Nerd Fonts v3.4.0 `JetBrainsMono.tar.xz` (sha256 `ef552a3e…1582`). The Regular, Bold, Italic and BoldItalic TTFs are in `vendor/fonts/jetbrains-mono-nerd-font/` together with `OFL.txt`; the licences are in THIRD_PARTY_NOTICES.
  - This is the "Nerd Font" variant, not "Nerd Font Mono": its icons are full-size and may span two cells. The renderer does not clip glyphs to their cell, so they draw correctly, whereas the Mono variant squeezes icons into one cell.
  - It adds about 9.9 MB to the exe.
  - Bump the font only in its own commit, like the other pins.
- **Loading:** `IDWriteFactory5` in-memory font loader → font set → private `IDWriteFontCollection`, built once per thread and cached. It needs Windows 10 1903+; on older systems Optimum falls back to Consolas.
- **Selection:** the `config.toml` `family` is looked up among the installed fonts first, so any installed font works, including per-user installs and any other Nerd Font. If it is not installed, the bundled font is used. Consolas is only the last resort.
  - Fallback for missing glyphs (CJK and so on) still goes through the system `IDWriteFontFallback`.
  - Default `family = "JetBrainsMono Nerd Font"` (it was Cascadia Mono in ADR-014).
- **Not done:** loading a font file by path without installing it. Add it if needed.

## ADR-021: No close confirmation

- **Date:** 2026-10-28
- **Decision:** closing the window through the OS (`Alt+F4`, the taskbar or `WM_CLOSE`) closes it immediately, even while the shell is alive. The confirmation panel from ADR-017 ("A process is still running. Close anyway?") is removed, together with its Enter/Esc modal keys.
- **Why:** a prompt is friction for the common case. Long-running work belongs in a multiplexer, which survives the window.
- **Unchanged:** the shell exiting still closes the window, and the overlay panel stays for the WSL-missing message.

## ADR-023: Clarity sign-off (M7)

- **Date:** 2026-10-28
- **Decision:** text clarity is accepted with the defaults. Antialiasing, gamma and enhanced contrast stay `"system"` (DirectWrite's `IDWriteRenderingParams`), the ClearType level is the system value, and the font is JetBrainsMono Nerd Font 12 pt with line height 1.0. No tuned constants are needed.
- **How it was judged:** by eye on a 144 DPI monitor, comparing the debug build with the tuner next to Windows Terminal 1.24 showing the same text and font.
  - The enhanced-contrast slider has almost no effect on light text on a dark background. The light-on-dark adjustment taken from DirectWrite/AtlasEngine scales contrast by `saturate(3 − 4·luminance)`, which is about 0 for `#d4d4d4`. This is expected, and it is the same in Windows Terminal.
- **Reference captures:** `docs/clarity/reference/`, PrintWindow crops at native pixels plus ×8 nearest-neighbour zooms, at 144 DPI. Caveat: in these captures Windows Terminal rendered **grayscale** (its profile used grayscale or a translucent background) while Optimum rendered **ClearType**, so they are not a like-for-like pair. Retake them with WT on ClearType and opacity 100% if a stricter comparison is wanted.
- **Not added:** config keys for the ClearType level and for a separate grayscale contrast. The tuner has them, but defaults were accepted; add the keys only on request.

## ADR-024: Own installer, `optimum-setup.exe` (Rust)

- **Superseded by ADR-025** the same day. The code was removed.

- **Date:** 2026-10-28
- **Decision:** a self-contained installer written in Rust, preferred over MSIX (which needs signing), winget (which creates no Start menu entry for a zip) or third-party installer tools (which would break the Rust-first rule).
- **What it does:** it installs for the current user only, with no administrator rights:
  - the payload goes to `%LOCALAPPDATA%\Programs\Optimum`, plus `uninstall.exe`, which is the installer stub without the payload;
  - it creates the Start menu shortcut `Programs\Optimum.lnk` (IShellLinkW);
  - it writes `HKCU\…\Uninstall\Optimum`: DisplayName, DisplayVersion, DisplayIcon, InstallLocation, UninstallString `"…\uninstall.exe" --uninstall`, NoModify, NoRepair, EstimatedSize;
  - the UI is the native Windows task dialog (`TaskDialogIndirect`, comctl32 v6 through an embedded manifest): a confirm page with **Install** (or **Update**) and Cancel, a progress page while a worker thread installs, then a finish page with a checked **Launch Optimum** box, or an error page with the error text. `--quiet` installs with no window and no launch.
- **Updates:** running copies from the install folder are stopped first. Each file is written as `*.new`, the existing file is renamed to `*.<stamp>.old` (Windows allows renaming a running exe), and the new file is moved in. Leftover `.old`/`.new` files are swept on the next install.
- **Uninstall:** the same dialog asks "Remove Optimum?" first (`--quiet` skips it). Running `uninstall.exe` without arguments also uninstalls. It stops running copies, deletes the files, the shortcut and the registry key, then removes `uninstall.exe` and the folder through a delayed hidden `cmd /c ping … & del … & rmdir`. `%APPDATA%\Optimum\config.toml` is kept.
- **Payload format:** the files are appended to the stub exe as `[u32 name length][name][u64 data length][data]…`, followed by a trailer `[u64 stub length][u32 count]"OPTPACK1"`. Names with path separators or `..` are rejected. Packing is done by `optimum-pack`, which runs on the host, so building the installer does not depend on building Optimum.
- **Icon and manifest:** the shared `optimum-icon` build helper embeds the same `.ico` in both exes, and in the installer also `setup.manifest` (common controls v6, PerMonitorV2, asInvoker).
- **Note on "no OS dialogs":** that rule is about the terminal. The installer is a separate program whose whole job is a short dialog.
- **Not done:** code signing (SmartScreen warns on first run), a choice of install folder, and a machine-wide install.
- **Verified:** Windows tests cover install into a temp folder (files, uninstaller, shortcut), replacement of a file held open the way a running exe is, the uninstall of that folder, and registry write and delete under a test key. The real installer was built and its icon checked.

## ADR-025: Installer with Inno Setup

- **Date:** 2026-10-28
- **Decision:** replace the Rust installer (ADR-024) with Inno Setup 6. Users expect the standard step-by-step wizard every Windows installer has; both the silent installer and the task-dialog version looked foreign. This is a deliberate exception to "Rust first": it touches only release packaging, never the app.
- **Script:** `installer/optimum.iss`. `WizardStyle=modern`, pages: licence (0BSD), install mode (current user by default, all users with elevation if chosen), folder, an unchecked desktop-shortcut task, progress, finish with "Launch Optimum". Fixed `AppId` `1191DD23-A70B-4FFB-B77D-37FE0F1A8601`. Default folder `{autopf}\Optimum`, which is `%LOCALAPPDATA%\Programs\Optimum` per user. `CloseApplications=yes` closes a running Optimum through Restart Manager before replacing files. 12 UI languages, chosen from the Windows UI language.
- **Uninstall:** Inno's uninstaller, registered in Installed apps. It removes only installed files; `%APPDATA%\Optimum\config.toml` is kept.
- **Images:** `installer/wizard-{100,125,150,200}.bmp` (164×314 at 100%) and `wizard-small-*.bmp` (55×55 at 100%), generated from the icon.
- **Tooling:** Inno Setup 6.7.3, sha256 `9c73c3bae7ed48d44112a0f48e66742c00090bdb5bef71d9d3c056c66e97b732` for `innosetup-6.7.3.exe`. The release workflow downloads it from the jrsoftware/issrc GitHub release, checks this hash and installs it portable (Chocolatey has no 6.7.3 package); locally it is the same portable install outside the repo. Inno Setup's licence allows redistributing installers built with it.
- **`optimum-icon`** goes back to embedding only the icon.
- **Icon refresh:** `ChangesAssociations=yes` makes Setup and Uninstall tell Explorer to refresh icons at the end, so shortcuts don't keep an icon cached from an earlier build at the same path.
- **Verified:** the script compiles with ISCC 6.7.3 into a 5 MB installer. The wizard is checked by hand on Windows.

## ADR-026: Standard system shortcuts

- **Date:** 2026-10-28
- **Decision:** the "one shortcut" rule covers features of the terminal itself: there are none besides `Ctrl+,`. Standard Windows text shortcuts are a different thing and all of them work, the same way as in Windows Terminal:
  - **Copy:** `Ctrl+C` copies and clears the selection when there is one; without a selection it goes to the shell as the interrupt. `Ctrl+Shift+C` and `Ctrl+Insert` always copy.
  - **Paste:** `Ctrl+V`, `Ctrl+Shift+V`, `Shift+Insert` (and right-click, ADR-017).
  - **Select all:** `Ctrl+Shift+A` (libghostty-vt `ghostty_terminal_select_all`). `Ctrl+A` stays with the shell (start of line, tmux prefix).
  - **Selection by keyboard:** with a selection active, `Shift+arrows` and `Shift+Home/End` extend it (`ghostty_terminal_selection_adjust`); without one, those keys go to the app. `Esc` clears an active selection and is not sent. Any input sent to the shell (keys, text, paste) also clears the selection.
  - **Scrollback:** `Shift+PageUp/PageDown` by a screen, `Ctrl+Shift+Up/Down` by a line, `Ctrl+Shift+Home/End` to top or bottom. On the alternate screen these keys go to the app.
  - **Window menu:** `Alt+Space` posts `WM_SYSCOMMAND/SC_KEYMENU`, which opens the system menu (move, size, minimise, close).
- **Matching:** letters are matched by virtual key, so they work on any layout (Cyrillic included); modifiers must match exactly, so `Ctrl+Alt+C` (AltGr) is untouched. A swallowed key's release is swallowed too, so apps with kitty release reporting never see a lone release.
- **Trade-off:** `Ctrl+V` no longer reaches the shell (`quoted-insert` in bash, block visual mode in vim; vim users can use `Ctrl+Q`). This matches Windows Terminal's defaults.
- **Also added** (same day): font zoom and full screen, see ADR-027.

## ADR-027: Font zoom, full screen, Shift+click

- **Date:** 2026-10-28
- **Decision:** three more everyday shortcuts, as in Ghostty and Windows Terminal. This drops "font zoom shortcuts" from the non-goals.
  - **Font size:** `Ctrl+=` (also `Ctrl+Shift+=` and numpad `+`), `Ctrl+-` (numpad `-`), `Ctrl+0` (numpad `0`) resets; `Ctrl`+wheel zooms by one point per notch, even when an app grabs the mouse. Steps are 1 pt, clamped to 4–96 pt. The zoom is an offset on top of `[font] size`, kept across config reloads and DPI changes, and never written to `config.toml`.
  - **Full screen:** `F11` or `Alt+Enter` toggles. The window drops `WS_OVERLAPPEDWINDOW` for `WS_POPUP`, covers its monitor (`rcMonitor`), loses rounded corners, and hit-tests as client only (no drag strip or resize edges). Leaving restores the style, corners and the saved `WINDOWPLACEMENT`, including the maximized state.
  - **Shift+click** with an active selection moves its end to the clicked cell and keeps the start; dragging with Shift held keeps extending; the result is copied on release. Without a selection, Shift+click starts a normal selection (the Shift mouse override from ADR-017 still applies).
- **Rejected:** a double `Esc` to close the window. Programs use `Esc Esc` all the time (Claude Code, vim, fzf, zsh vi-mode), and closing has no confirmation (ADR-021).

## ADR-028: macOS port, first steps

- **Date:** 2026-10-28
- **Decision:** the macOS port starts now. Targets: **Apple Silicon only** (`aarch64-apple-darwin`), macOS 13 or newer. Intel Macs are not built.
- **Development loop:** code is written in WSL. `cargo-zigbuild check/clippy --target aarch64-apple-darwin` works there without an Apple SDK (Zig cross-builds libghostty-vt for `aarch64-macos`); linking and tests need macOS, so CI runs a `macos-15` job (`cargo clippy` + `cargo test`). There is no remote access to a Mac: builds are checked by hand from CI artifacts.
- **PTY:** `UnixPty` in `optimum-mac` uses `openpty`, `setsid` + `TIOCSCTTY` in the child, `TIOCSWINSZ` for resize, a reader thread and a waiter thread, the same shape as `WinPty`. The shell is the user's login shell from `getpwuid_r` (then `$SHELL`, then `/bin/zsh`), started as a login shell (`argv[0]` = `-zsh`) in the home directory, with `TERM`, `COLORTERM`, `TERM_PROGRAM`, `TERM_PROGRAM_VERSION` set. The module only needs Unix, so its tests also run on Linux; it can move to a shared crate when the Linux port starts.
- **Shared rendering:** the glyph atlas and the instance building (rows, backgrounds, underline/strikethrough, cursor shapes, overlay panel, error strip, IME preedit) moved from `optimum-win` into `optimum-core::scene`, as §4 of the brief places glyph atlas logic in the core. A platform implements `GlyphSource` (metrics, lookup, rasterize, shading) and only uploads `Scene::take_uploads()` and draws `Scene::instances()`. Windows output is unchanged. A `COLOR` shading value is reserved for colour glyphs (emoji), which keep their colours under the block cursor.

## ADR-029: macOS app, first version

- **Date:** 2026-10-28
- **Decision:** the first runnable macOS app covers window, text, input and the daily basics in one step, because it can only be checked by hand from a CI artifact.
  - **Window:** one `NSWindow` with `Titled | Closable | Miniaturizable | Resizable | FullSizeContentView`, transparent hidden title, the three buttons hidden and the titlebar container hidden, so the content gets every click while the window keeps rounded corners, shadow, resize and native full screen. Automatic tabbing is off (`setAllowsAutomaticWindowTabbing(false)`, `tabbingMode = Disallowed`). The top padding is the drag strip (`performWindowDragWithEvent`, double click zooms). Closing the window quits the app.
  - **Single instance:** `LSMultipleInstancesProhibited` in `Info.plist`, plus a `flock` on `~/Library/Application Support/Optimum/instance.lock`; a second process started directly activates the first through `NSRunningApplication` and exits. Bundle identifier `dev.optimum.Optimum`.
  - **Menu:** only the app menu: Settings… (`Cmd+,`), Hide (`Cmd+H`), Quit (`Cmd+Q`).
  - **Rendering:** a `CAMetalLayer` in sRGB, BGRA8, one instanced draw of the shared `Scene` (ADR-028) with an MSL shader compiled at start-up. CoreText implements `GlyphSource`: the configured family if installed, otherwise the bundled JetBrains Mono Nerd Font (registered from memory), otherwise Menlo; fallback through `CTFontCreateForString`; colour fonts (emoji) are rasterized in RGBA and drawn as `COLOR`. Glyphs are grayscale with font smoothing off; clarity tuning is M7.
  - **Font size:** points are logical pixels, so `size = 12` is 12 pt at 1× and 24 device pixels on Retina.
  - **Input:** `keyDown` runs `interpretKeyEvents` so dead keys and IME go through `NSTextInputClient`; the collected text, the physical key (from the ANSI key code), the modifiers and the unshifted character go to libghostty-vt's key encoder. Option produces characters (it is not Meta). Marked text is drawn as the preedit at the cursor.
  - **Shortcuts** (macOS equivalents of ADR-026/027): `Cmd+C` copies the selection, `Cmd+V` pastes, `Cmd+A` selects all, `Shift+arrows` and `Cmd+Shift+←/→` extend a selection, `Esc` clears it, `Shift+PageUp/PageDown` and `Cmd+PageUp/PageDown` page, `Cmd+↑/↓` scroll a line, `Cmd+Home/End` jump, `Cmd+=`/`Cmd+-`/`Cmd+0` zoom, `Ctrl+Cmd+F` full screen, `Cmd+W` closes, `Cmd+M` minimizes, `Cmd+,` settings.
  - **Mouse:** select-to-copy, double/triple click, Shift+click extends, right-click pastes, Shift overrides app mouse mode, wheel and trackpad scroll the scrollback or report to the app.
  - **Settings:** `~/Library/Application Support/Optimum/config.toml`, opened with `open -t`, reloaded by polling its modification time every 400 ms.
  - **Shell environment:** `LANG=en_US.UTF-8` is set when the app inherits no `LANG` (apps started from Finder get a bare environment).
- **Packaging for testing:** CI builds `Optimum.app` (`installer/macos/bundle.sh`: `Info.plist`, `.icns` made with `sips` and `iconutil` from `assets/png/optimum-256.png`, ad-hoc `codesign`) and uploads `Optimum-macos.zip` as a workflow artifact. Tagged releases also attach `Optimum-<version>-macos-arm64.zip` and its checksum. The app is not signed with a Developer ID or notarized; after download run `xattr -dr com.apple.quarantine Optimum.app`. The new crates (objc2 family, block2, dispatch2, bitflags, libc) are listed in `THIRD_PARTY_NOTICES.md` under MIT.
- **Not yet verified** on a real Mac: everything above. It compiles and passes clippy for `aarch64-apple-darwin`; the PTY and keyboard tests pass on Linux.
